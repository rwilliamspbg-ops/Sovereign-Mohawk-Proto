# ZK Weight-Update Circuit (Pillar 1)

## Status

`circuits/src/main.nr` is the **specification**: a Noir 1.0 circuit that compiles
in CI (`nargo compile` + `nargo test`, `.github/workflows/noir-circuit-check.yml`).
It is not wired to a prover and has no Go binding.

The executable circuit is **`internal/zkweight_circuit.go`**
(`WeightUpdateCircuit`, gnark / Groth16 / BN254), ported from this specification
and wired into `internal/zkprover`, `internal/batch` and `internal/pyapi`. See
`docs/ZK_FINALIZATION_PLAN.md` for the backend decision and its rationale.

## Public inputs

- `model_hash_before: Field` — hash of the model before training.
- `model_hash_after: Field` — hash of the model after training.
- `dataset_commitment: Field` — commitment to the local training batch.
- `grad_norm_bound: Field` — maximum allowed L2 norm of the gradient.
- `dp_epsilon: Field` — differential-privacy budget.
- `update_hash: Field` — hash of the compressed update sent to the aggregator.

## Private inputs

- `gradients: [Field; 8]` — the computed gradient vector.
- `noise: [Field; 8]` — DP noise added before compression.
- `training_steps: u32` — number of local SGD steps.

## Constraints (what `main.nr` actually implements)

1. **Training occurred**:
   `model_hash_after == pedersen_chain(model_hash_before, training_steps, gradients)`.
2. **Norm bound**: each `gradients[i]` is range-checked to 64 bits, and
   `sum(gradients[i]^2) <= grad_norm_bound^2` is compared in `u128`.
3. **Update hash binding**:
   `update_hash == pedersen_chain(dp_epsilon, training_steps, gradients[i]+noise[i]…, dataset_commitment)`.
4. **Dataset binding**: `dataset_commitment != 0`.

The gnark port uses MiMC instead of pedersen, and Q32.32 fixed-point components
instead of raw field elements; see the encoding contract in
`internal/zkweight_circuit.go`.

## Not implemented (do not cite)

- `dp_delta` is **not** a public input of `main.nr`. Earlier revisions of this
  README listed it; the circuit has no such parameter.
- There is **no compression step** and no
  `update_hash == hash(compress(noisy_grad))` constraint. Constraint 3 hashes
  the noised gradients directly; nothing models a compressor.
- There is **no range proof and no committed randomness seed** for the DP noise.
  Beyond the 64-bit range check, `noise` is an unconstrained private input, so
  the circuit does not verify that the noise distribution was calibrated.

## Verification

The aggregator verifies the proof in O(1) pairing time. A missing or invalid
proof causes the update to be rejected (fail-closed) — see
`internal/batch/aggregator.go`.

Measured cost of the gnark port (8 gradients, 9569 constraints, BN254):
verify **0.67 ms**, prove **34 ms**, proof **164 B**, one-time trusted setup
**44 s**. Source: `results/zk/weight-proof-latest.json`, regenerated by
`cmd/zkweightbench` in `.github/workflows/zk-circuit-gate.yml`.
